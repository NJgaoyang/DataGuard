# DataGuard 控制台使用指南

访问 DataGuard HTTPS 管理后台后，通过个人会话登录。外部 MCP/REST 使用 Agent Token，二者不能混用。用户角色为 `ADMIN`、`APPROVER` 和 `READER`；按钮的可见性不是唯一权限验证，后端仍强制校验。

## 1. 工作台

显示访问次数、成功率、待处理审批、拒绝等指标以及最近访问。点击指标卡可能跳转到筛选后的访问记录/审批页面。最近访问列表带序号。

## 2. 数据源

1. 新增 MySQL / StarRocks，配置连接地址、数据库、**物理只读账号**。
2. 使用平台提供的连接测试确认网络与数据库 TLS/只读账号有效。
3. 按需要启用物理表及字段白名单；禁止为便利直接开放整库敏感表。
4. 数据源停用会使相关查询不可用。修改凭据时只使用安全配置，不在审计或 README 中保留明文。
5. 源、表、字段列表增加连续序号；主列表翻页时序号不从 1 重新开始。

## 3. Agent 管理与 Token

Agent 运行状态只有两种：

| Agent 状态 | 编辑授权 | 状态操作 | 删除 |
|---|---|---|---|
| **启用** | 禁用，需先停用 | 停用 Agent | 禁用 |
| **已停用** | 允许编辑平台已授权范围内的源/表/列 | 启用 Agent | 允许软删除 |

- 首次创建的 Token **仅展示一次**，请保管在客户端私有凭据区。
- 普通停用不允许 Agent 再查询；若 Token 仍有效且未被重签，重新启用可继续使用旧 Token。
- Token **轮换**是独立的安全动作，旧 Token 即时永久失效，新 Token 只展示一次。
- 早期「已撤销」已迁为「已停用」，被撤销的旧凭据永久废弃；首次重新启用自动生成新 Token。
- 已过期凭据在重新启用时自动重签。不要把「Token 已过期」误当成第三种运行状态。
- 删除为**软删除**：必须先停用；列表隐藏 Agent、禁用凭据与关联规则、撤销表字段授权，并保留旧审批/审计记录供追溯。
- Agent 详情中的使用情况会展示最近访问，含序号和查询状态。

## 4. 访问规则

根据业务需要配置 `ALLOW`（允许）、`APPROVAL`（人工审批）或 `DENY`（拒绝）。规则可关联源、Agent、表、字段、单次读取行数等条件。

- 规则由后端按 `DENY` 优先、再 `APPROVAL`、最后 `ALLOW` 处理，无匹配默认拒绝。
- 被设为审批的规则必须选用有权限且有效的独立审批账号；申请人不得审批自己请求。
- 审批通过不会绕过最基础的表列授权；改动规则会影响后续 SQL 或执行后复核。
- 规则管理主列表含序号；修改或停用规则前应评估现有 Agent 的查询行为。

## 5. 审批中心

四个范围的含义：

| 标签 | ADMIN | APPROVER | READER |
|---|---|---|---|
| **全部申请** | 当前系统所有申请与执行记录 | 不展示 | 不展示 |
| **待我审批** | 所有有效的、非本人发起且可由管理员处理的 PENDING | 仅指派本人且非本人发起的有效 PENDING | 不展示 |
| **我发起的** | 当前账号本人申请 | 本人申请 | 本人申请 |
| **已处理** | 已完成或拒绝的请求，包括自动执行成功 | 指派本人且不再是 PENDING / EXECUTING 的记录 | 不展示 |

切换标签会重新请求后端并清空旧显示数据，较慢的旧请求不会覆盖当前所选标签。如果暂时没有 PENDING，「全部申请」和「已处理」可能高度重合，属于正常结果。

审批动作必须携带理由，由有权决定该申请的用户执行。已过期、已处理或申请人本人的审核会被后端拒绝。

## 6. 访问记录

### 当前筛选交互

- **默认日期：当天**。开始日期和结束日期均按使用者浏览器日期初始化。
- 过滤项：状态、Agent、数据源、日期范围、搜索文本（可查表名、请求编号和脱敏 SQL 模板）。
- Agent 和数据源候选项来自 `GET /api/requests/filters`，独立于当前页面与当前选中条件；选中一个后可以**直接切换到另一个**，不必先选“全部”。
- **修改筛选选项不会立即查询**。只有点击 **查询** 才应用当前条件，跳回第一页执行检索。
- **重置**只将输入恢复为：全部状态、全部 Agent、全部数据源、搜索为空、日期当天；**不会立即查询**。需要点击查询才会更新列表。
- 翻页使用最后一次真正查询时的条件，未提交的筛选输入不影响已载入结果；访问记录后端每页固定 10 条。
- 快速连续查询时只采纳最新请求的返回结果，避免旧 HTTP 响应覆盖较新筛选。

### SQL 审计与详情

访问记录列表包含 SQL 摘要；点击“查看”显示脱敏 SQL 模板和请求字段、行数、规则与状态。字面量与 JDBC 绑定参数值不落审计；旧历史记录若无 SQL，则展示「历史记录未保存 SQL」。不应从模板猜测查询真实参数。

状态例如 `SUCCESS`、`PENDING`、`APPROVED`、`DENIED`、`REJECTED`、`FAILED`，不等同于 Agent 是否启用。管理员可见全局，其他用户只能按归属与审批权限查看记录。

## 7. 系统设置与账号安全

管理员可维护用户、角色、账号状态、密码策略、Agent 调用/行数额度及 SQL 白名单函数。后台写操作受 CSRF 与角色校验约束；初始管理员必须及时修改初始密码。

登录失败有用户名维度临时锁定；公网正式使用仍需考虑反向代理 IP/路径级防护。Token 不应写入聊天记录、工单附件或仓库。
