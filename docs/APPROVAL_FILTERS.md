# 审批中心四类筛选的业务语义

| 标签 | 管理员（ADMIN） | 审批人（APPROVER） | 普通用户（READER） |
|---|---|---|---|
| 全部申请 | 所有申请与执行记录，含直接放行和直接拒绝 | 不展示此标签 | 不展示此标签 |
| 待我审批 | 所有未过期、PENDING 且申请人并非本人、当前有权限处理的请求 | 指派给本人、未过期、PENDING 且本人不是申请人的请求 | 不展示 |
| 我发起的 | 自己作为申请人提交的记录 | 自己作为申请人提交的记录 | 自己作为申请人提交的记录 |
| 已处理 | 所有非 PENDING / EXECUTING 的历史记录，包括系统自动成功与拒绝 | 指派给本人且已不在 PENDING / EXECUTING 的历史记录 | 不展示 |

筛选条件在后端 `GET /api/requests?scope=all|pending|mine|handled` 中以带参数的 SQL 生效。
前端使用 `v-model:value` 同步单选标签，每次切换重新请求后端并清除旧列表；
请求序号只允许最后一次点击对应的响应更新 UI，避免连续切换标签时旧响应覆盖新结果。

“已处理”指全部处理结果，不仅限人工签字的申请：自动执行成功与直接拒绝也需要完整追溯，因此管理员可在这里查看对应记录。
“我发起的”不等于“我可以审批”；管理员没有亲自发起申请时，该标签正常显示空结果与原因。

安全说明：`scope=all` 对非管理员仅返回本人记录，`pending`、`handled` 对无审批权限的普通用户返回 HTTP 403。
管理员可以处理任意**非本人**待审请求，非管理员审批人只能处理其被指派的请求。
后端执行审批时继续严格验证独立审批人、申请状态、有效期与账号权限，不因更改筛选范围而放宽审批权限。

当前审批中心的列表单次最多返回最新 300 条；如数据规模超过该阈值，后续可升级为服务端分页，不应把客户端筛选用作跨全部历史记录的精确查询。
